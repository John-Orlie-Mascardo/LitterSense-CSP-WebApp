### Delivery limits

- Server gas and abnormal-health alerts can send while all browsers are closed. Existing normal RFID entry/exit notification creation still requires an open dashboard. This separate existing limitation was reported, not silently redesigned.
- Registration requires Firestore availability to confirm the user document write. Once registered, delivery can use previously mirrored recipients/tokens during quota outages.
- Provider acceptance is not proof that a phone displayed a message. Actual SMS and push delivery require user confirmation.
- Ambiguous sends are marked unknown rather than blindly retried. A partly successful multi-device push batch is not resent to successful devices. This avoids duplicates but can leave a transiently failed device without that alert.

#### Optional authenticated SMS test

Refresh the signed-in site first. Open browser Developer Tools > Console and run this on your own LitterSense site. It uses your existing login locally, sends one test, and prints only the response, never the login token. Close the console afterward.

```js
const smsTestDb = await new Promise((resolve, reject) => {
  const open = indexedDB.open('firebaseLocalStorageDb');
  open.onsuccess = () => resolve(open.result);
  open.onerror = () => reject(open.error);
});
const smsTestRows = await new Promise((resolve, reject) => {
  const request = smsTestDb.transaction('firebaseLocalStorage', 'readonly')
    .objectStore('firebaseLocalStorage').getAll();
  request.onsuccess = () => resolve(request.result);
  request.onerror = () => reject(request.error);
});
smsTestDb.close();
const smsTestLogin = smsTestRows.find(row => row.fbase_key?.endsWith(':[DEFAULT]')
  && row.value?.stsTokenManager?.accessToken);
if (!smsTestLogin) throw new Error('Sign in and refresh before testing.');
const smsTestResponse = await fetch('/api/sms/test', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json',
    Authorization: `Bearer ${smsTestLogin.value.stsTokenManager.accessToken}` },
  body: JSON.stringify({ confirmed: true })
});
console.log('SMS test:', smsTestResponse.status, await smsTestResponse.json());
```

### Push

1. Open the deployed HTTPS site. On iPhone, use iOS 16.4+ and add it to Home Screen first; open the installed app.
2. Settings: tap Enable push notifications, allow the browser prompt, and confirm registration succeeds.
3. Tap Send test push. Keep the app open for the foreground notice. Then close/minimize it and repeat after the one-hour limit for background delivery. Quiet hours apply to tests too.
4. Repeat registration on a second device signed into the same account. A test should reach both eligible devices without duplicate notifications per device.
5. Tap a notification to open the dashboard. Sign out; future alerts should no longer reach that signed-out device.
6. During ordinary use, confirm a supported server health/environment alert arrives with the website closed. RFID entry/exit remains subject to the open-dashboard limitation above.
7. Check Home at phone and desktop widths; brain and bell should align. Add Cat should reject typing and accept the existing three-scan flow.
